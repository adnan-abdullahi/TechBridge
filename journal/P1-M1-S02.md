# P1-M1-S02 — Documenting the Engineering Workspace

**Phase:** P1 — Engineering Foundations  
**Milestone:** M1 — Professional Engineering Environment  
**Session:** S02

---

## 1. Session Objective

Document the structure of the TechBridge engineering workspace and establish clear responsibilities for each top-level directory.

---

## 2. What Was Built

The following directories were documented:

- `app/` — Application source code
- `docs/` — Official engineering documentation
- `journal/` — Engineering learning and session records
- `diagrams/` — System and architecture diagrams
- `assets/` — Supporting project resources
- `experiments/` — Experimental work and prototypes
- `archive/` — Historical project artifacts

Each directory now contains a `README.md` explaining its purpose.

---

## 3. Engineering Concepts Learned

### Git Working Directory

The working directory contains the files being created and modified.

### Git Staging Area

The staging area contains changes selected for the next commit.

### Git Commit

A commit records a permanent checkpoint in local Git history.

### Git Remote

A remote is another repository that the local repository communicates with.

### Git Push

`git push` publishes local commits to the remote repository.

### Git Status

`git status` allows the engineer to inspect the current state of the repository.

---

## 4. Important Discovery

Git tracks files rather than empty directories.

Therefore, an empty directory does not appear on GitHub.

Adding a meaningful `README.md` gives the directory both documentation and a tracked file.

---

## 5. Engineering Practice

The session reinforced the following workflow:

Plan → Build → Inspect → Verify → Commit → Push → Reflect

The workflow emphasizes verification before committing or publishing changes.

---

## 6. Challenges Encountered

The folder name `experiments` was initially misspelled as `expirements`.

The error was detected during inspection before the files were staged and committed.

The directory was corrected before continuing.

---

## 7. Reflection

This session demonstrated that engineering is not simply about producing files or writing code.

Organization, documentation, verification, version control, and communication are also engineering activities.

The repository is beginning to represent not only the software being built, but also the reasoning and learning process behind it.

---

## 8. Result

The TechBridge engineering workspace is now documented and published on GitHub.

The repository contains a clear structure for application code, documentation, diagrams, assets, experiments, archives, and engineering records.
